# The Diet App

Приложение для расчёта питания (КБЖУ) и диет для разных групп здоровья.
Реализованы:
- модуль нормы калорий и БЖУ (с учётом заболеваний и стадий жизни);
- база продуктов из двух источников (USDA + Open Food Facts) с гликемическим
  индексом (ГИ) и метками совместимости с диабетом;
- **база данных** (SQLite локально / PostgreSQL в проде) с дневником питания
  и пользователями;
- **гликемическая нагрузка (ГН)** — аддитивная метрика качества углеводов,
  ключевая для диабета: проверка порций, приёмов пищи и итогов дня;
- **UI-каркас «Vivora»** (`web/`) — React + Vite + TypeScript + Tailwind:
  28 экранов (дневник, поиск продуктов, AI-ассистент, профиль, онбординг…),
  дизайн-система (палитра/типографика/тени). Пока работает на мок-данных,
  интеграция с backend — следующий этап.


> Готовые таблицы в `data/processed/` — компактные, можно работать без дампа.

## База данных и дневник питания

Помимо CSV-таблиц, есть полноценная БД (`diet/db.py`, схема `diet/schema.sql`):
- **SQLite локально** (`data/diet.db`) — без сервера, для разработки и ноутбуков;
- **PostgreSQL в проде** — управляемый инстанс РФ-провайдера, через `DIET_DB_URL`.

Таблицы: `products` (справочник с ГИ и метками диабета), `users` (профили + нормы),
`diary_entries` (записи дневника: продукт + граммы + приём пищи + день).

ГН не хранится — считается на лету (`gi/100 × углеводы × масса/100`), т.к.
зависит от порции и аддитивна. Итоги дня/приёма агрегируются SQL-запросом с JOIN.

### Миграция данных в БД

```bash
# Заполнить БД из unified_foods.csv (~31 тыс. продуктов, идемпотентно):
./.venv/Scripts/python.exe scripts/06_load_db.py
```

### Подключение PostgreSQL (продакшен)

```bash
# 1. Поднять managed PostgreSQL у РФ-провайдера (Selectel / Timeweb / Cloud.ru / VK).
# 2. Установить драйвер:
./.venv/Scripts/python.exe -m pip install "psycopg[binary]"
# 3. Задать URL и мигрировать:
DIET_DB_URL=postgresql://user:pass@host:5432/dbname \
    ./.venv/Scripts/python.exe scripts/06_load_db.py
```

Слой `diet/db.py` диалектно-нейтрален: те же функции `init_db`,
`search_products`, `add_entry`, `day_totals` работают с обоими движками.

## Гликемическая нагрузка (ГН)

ГИ — индекс конкретного продукта (0..100). **ГН — аддитивная метрика**, её
можно складывать по ингредиентам блюда и за день:

```
ГН порции = (ГИ / 100) × углеводы порции (г)
```

Поэтому «рис + мясо»: мясо даёт ГН ≈ 0 (углеводов нет), рис — основную ГН
блюда. «Рис нельзя диабетику» = «нельзя **большую** порцию», а не запрет.

Нормы при диабете (`conditions.diabetes_t2.gl_targets`):
- приём пищи ≤ 15 (warn), день < 80;
- проверки: `diet.checks.check_gl_portion` / `check_gl_meal` / `check_gl_day`.

См. `notebooks/07_glycemic_load_demo.ipynb` — сквозное демо.

## HTTP API (`diet/api.py`)

Мост между доменной логикой (`diet/`) и UI Vivora (`web/`). FastAPI, все
эндпоинты под `/v1` (задел под версионирование). Документация автоматически
доступна после запуска на `/docs`.

```bash
uvicorn diet.api:app --reload        # http://127.0.0.1:8000, docs на /docs
```

Эндпоинты делятся на публичные (поиск/расчёт — нужны до регистрации) и
защищённые (дневник — требуют JWT):

- `POST /v1/auth/register` — регистрация: профиль + email/пароль, считает
  норму КБЖУ, возвращает `access_token` + профиль (пользователь сразу залогинен);
- `POST /v1/auth/login` — логин по email/паролю → `access_token`;
- `GET  /v1/auth/me` — текущий профиль по токену;
- `GET  /v1/products?search=рис&limit=20` — поиск по названию (кириллица,
  с приоритетом «слово с начала»);
- `GET  /v1/products/{id}` — карточка продукта (404 если нет);
- `POST /v1/diary` — добавить порцию в дневник (текущий пользователь из токена);
- `GET  /v1/day-summary?day=YYYY-MM-DD` — итоги дня (КБЖУ + ГН) со списком
  порций и предупреждениями проверок;
- `POST /v1/calculate` — рассчитать норму КБЖУ без сохранения (публичный);
- `GET  /v1/checks?day=YYYY-MM-DD` — только проверки (микроэлементы + ГН).

Валидация входов — Pydantic-схемы в `diet/schemas.py` с enum'ами по
настоящим ключам доменных справочников (`ACTIVITY_LEVELS`, `CONDITIONS`,
`LIFE_STAGES`, ...): некорректное значение отсекается на 422 ещё до входа в
эндпоинт, с перечнем допустимых в OpenAPI.

### Аутентификация

JWT (HS256). Пароли хранятся как bcrypt-хеши (`diet/auth.py`), в `users`
есть колонки `email` и `password_hash` (добираются миграцией в `init_db`,
старые профили сохраняются). Срок жизни access-токена — 7 дней; refresh-токенов
в MVP нет (по истечении — повторный логин). Текущий пользователь в защищённых
эндпоинтах берётся из токена (`Depends(get_current_user)`), `user_id` в
параметрах не передаётся.

Секрет подписи — `DIET_JWT_SECRET` в `.env` (см. `.env.example`). Без
переменной используется случайный ephemeral ключ с предупреждением: подходит
для локальной разработки, но токены инвалидируются при рестарте процесса.

```bash
# Заголовок для защищённых запросов:
Authorization: Bearer <access_token>
```

Соединение с БД открывается на каждый запрос — корректно для SQLite и
достаточно для MVP; при переходе на PostgreSQL можно ввести пул соединений.

## Что считает модуль КБЖУ

- **BMR** (базовый обмен) — две формулы на выбор, обе выводятся в таблице сравнения:
  - `who` — уравнения Скофилда, официальный стандарт ФАО/ВОЗ/ООН (4 возрастные группы);
  - `mifflin` — формула Миффлина–Сан Жеора (современная, часто точнее).
- **TDEE** — расход за день = BMR × коэффициент активности.
- **Целевые ккал** — TDEE с поправкой на цель (−500 / 0 / +300), не ниже
  безопасного минимума (жен. 1200 / муж. 1500 ккал).
- **БЖУ** — зависит от нозологической группы (`condition`) и стадии жизни (`life_stage`).

Параметры: `formula`, `condition`, `life_stage`. При конфликте белка между болезнью
и стадией жизни приоритет у ХБП (защита почек); рискованные комбинации отмечаются
в `result.warnings`.

### Нозологические группы (`condition`)

Белок может задаваться долей энергии (%) или граммами на кг веса (г/кг).
Жиры ≤30%, углеводы — остаток от калорий.

| Ключ | Группа | Белок | Источник |
|---|---|---|---|
| `healthy` | Здоровый взрослый | 15% | ВОЗ 2023 |
| `diabetes_t2` | Сахарный диабет 2 типа | 18% (15–20%) | ADA / Diabetes Canada |
| `obesity` | Ожирение / снижение веса | **1,3 г/кг** | Obesity Society (1,2–1,6 г/кг) |
| `ckd` | ХБП, стадии 3–5 (без диализа) | **0,8 г/кг** | KDIGO 2024 / KDOQI 2020 |
| `cvd` | ССЗ / гипертония | 15% (жиры ≤30%) | AHA |

### Стадии жизни (`life_stage`)

Ортогональны болезням — описывают здорового человека с особыми потребностями.

| Ключ | Стадия | Белок | Калории | Источник |
|---|---|---|---|---|
| `default` | Обычный взрослый | (по condition) | (по цели) | — |
| `athlete_endurance` | Спортсмен на выносливость | **1,3 г/кг** | — | ISSN (1,0–1,6) |
| `athlete_strength` | Спортсмен-силовик / набор | **1,8 г/кг** | — | ISSN (1,6–2,0) |
| `older_adult` | Пожилой (60+) | **1,1 г/кг** | — | PROT-AGE (1,0–1,2) |
| `pregnant` | Беременность (2–3 триместр) | **+25 г** | **+340 ккал** | NAM / RDA |
| `lactating` | Кормление грудью | **+25 г** | **+500 ккал** | NAM / RDA |

> ⚠️ Расчёт ориентировочный, не заменяет консультацию врача/диетолога.
> Качественные ограничения (натрий, насыщенные жиры, пурины) заработают
> по-настоящему после подключения базы продуктов — пока только текстовые
> рекомендации в `result.notes`.
